## 🌐 درباره پروژه

**Arya Messenger** یک پروژه مستقل اندرویدی با رویکرد **Local-First** است که با هدف ایجاد بستری برای ارتباط مستقیم بین دستگاه‌ها توسعه داده می‌شود.

هدف آریا، فراهم‌کردن زیرساخت پیام‌رسانی بدون وابستگی اجباری به یک سرور مرکزی دائمی است.

در نسخه فعلی، علاوه بر هویت دیجیتال و ارتباط امن آزمایشی یک‌به‌یک در شبکه محلی، مدیریت عضویت گروه و رمزنگاری محلی پیام‌های متنی گروهی با کلیدهای دوره‌ای نیز پیاده‌سازی شده است.

> آریا هنوز MVP آزمایشی است. گروه‌ها در این نسخه فقط روی همان دستگاه مدیریت و رمزنگاری می‌شوند؛ توزیع کلید و تحویل پیام گروهی بین دستگاه‌ها، ارتباط اینترنتی سراسری و رمزنگاری at-rest کامل پیام‌های خصوصی در مراحل بعدی قرار دارند.

## ✨ قابلیت‌ها

### 🔐 هویت دیجیتال و مدیریت مخاطبان

- تولید کلید امضای P-256 در Android Keystore
- نگهداری کلید خصوصی در محیط Android Keystore
- ایجاد کارت هویت عمومی به‌صورت QR Code
- تولید اثر انگشت SHA-256 از کلید عمومی
- اسکن و اعتبارسنجی QR مخاطبان
- ذخیره مخاطبان با استفاده از Room
- امکان تأیید دستی اثر انگشت مخاطبان

### 💬 گفتگو و پیام‌رسانی

- ایجاد گفتگوهای محلی
- ساخت گروه با انتخاب مخاطبان تأییدشده
- مدیریت اعضا توسط سازنده گروه
- ثبت تاریخچه عضویت و چرخش کلید با هر تغییر اعضا
- رمزنگاری و امضای پیام متنی گروهی با کلیدهای epoch
- ذخیره envelope رمزنگاری‌شده پیام گروه در پایگاه داده محلی
- ذخیره پیوست در گفتگوهای خصوصی؛ پیوست گروهی تا آماده‌شدن رمزنگاری فایل غیرفعال است
- انتخاب و پیوست فایل تا سقف ۲۰ مگابایت
- رابط کاربری چت با حباب پیام
- نمایش تاریخ و زمان پیام‌ها
- کارت‌های پیوست و نوار ورودی پیام

### 📡 ارتباط با دعوت (QR / لینک)

- تنها راه اتصال: یک دعوت. QR، لینک کپی‌شده و متن چسبانده‌شده همه یک چیزند
- یک پورت برای همه‌چیز: نشست مستقیم (`ARY4`) و جفت‌سازی رله (`ARYR`) روی همان پورت جدا می‌شوند
- هیچ صفحهٔ تنظیمات شبکه‌ای وجود ندارد؛ آدرس و سوییچ نود رله داخل پنجرهٔ دعوت است
- جفت‌سازی رله با شناسه چرخشی ۱۵ دقیقه‌ای، غیرقابل اتصال به هویت
- تبادل کلید موقت P-256 ECDH و مشتق‌سازی کلید با HKDF-SHA-256
- رمزنگاری رکوردها با AES-256-GCM و ردکردن بازپخش/ترتیب نامعتبر

### 🎨 رابط کاربری و شخصی‌سازی

- طراحی رابط کاربری با Jetpack Compose
- ناوبری مبتنی بر Navigation Compose
- پشتیبانی از تم روشن، تاریک و هماهنگ با سیستم
- ذخیره تنظیمات ظاهری در SharedPreferences
- پشتیبانی از Back Stack و دکمه بازگشت سیستم
- آیکون Adaptive، Monochrome و Mipmap

### 😀 سیستم ایموجی

- Emoji Picker تصویری
- دسته‌بندی ایموجی‌ها
- جست‌وجوی ایموجی
- نمایش ایموجی‌های اخیر
- پشتیبانی از تنوع رنگ پوست
- درج کاراکتر Unicode ایموجی در پیام
- نمایش تصویری ایموجی‌ها در گفتگوها

## 🛡️ امنیت و حریم خصوصی

امنیت یکی از اصول مهم طراحی آریا است؛ با این حال، نسخه فعلی هنوز زیرساخت امنیتی کاملی ندارد.

### موارد پیاده‌سازی‌شده در کد فعلی

- [x] تولید کلید هویت P-256 در Android Keystore
- [x] کارت هویت QR و اثر انگشت SHA-256
- [x] تأیید دستی مخاطب با مقایسه اثر انگشت
- [x] امضای transcript کامل handshake توسط هر دو طرف
- [x] الزام تأیید هویت هر دو طرف از فهرست مخاطبان محلی
- [x] تبادل کلید موقت ECDH و مشتق‌سازی کلیدهای جهت‌دار با HKDF-SHA-256
- [x] رمزنگاری AES-256-GCM با شماره توالی و ردکردن replay/tampering
- [x] حذف مسیر fallback متن ساده در TCP

### موارد باقی‌مانده

- [ ] رمزنگاری at-rest پیام‌های خصوصی و فایل‌ها
- [ ] اجرای تست کامل Android و تست دو دستگاه روی Android Keystore واقعی
- [ ] پروتکل نشست پایدار و ratchet برای پیام‌رسانی آفلاین/چندپیامی
- [x] رمزنگاری متن گروهی محلی، تاریخچه عضویت و چرخش کلید epoch
- [ ] توزیع امن کلید گروه و تحویل پیام گروهی بین دستگاه‌ها (فاز ۶)
- [ ] ارتباط اینترنتی سراسری، NAT traversal و رله/گره‌ها (فاز ۶)

### ⚠️ مرز امنیتی نسخه فعلی

کد فعلی مسیر TCP محلی را با handshake امضاشده و رمزنگاری نشست محافظت می‌کند؛ اما هنوز نباید آن را پیام‌رسان امنِ آماده انتشار عمومی دانست.

- هر دو دستگاه باید قبلاً کلید عمومی یکدیگر را از طریق QR و مقایسه مستقل اثر انگشت تأیید کرده باشند.
- پیام‌های متنی جدید گروه در پایگاه داده به‌صورت envelope رمزنگاری‌شده ذخیره می‌شوند و کلیدهای epoch با Android Keystore محافظت می‌شوند؛ اما پیام‌های گروهی قدیمی، پیام‌های خصوصی و فایل‌های ذخیره‌شده هنوز رمزنگاری at-rest ندارند.
- این پروتکل فعلاً یک پیام در هر نشست TCP را پوشش می‌دهد و جایگزین پروتکل کامل پیام‌رسانی اینترنتی نیست.
- اتصال LAN به معنی امکان اتصال از هر نقطه ایران نیست؛ مسیر اینترنتی و رله‌ها در فاز ۶ طراحی می‌شوند.
- تست loopback محلی موفق بوده، اما تست دو گوشی و تست نهایی Android Keystore هنوز انجام نشده است.

از اطلاعات حساس در نسخه آزمایشی استفاده نکنید.

## 🚀 نصب و اجرا

### پیش‌نیازها

| ابزار | نسخه |
|---|---|
| JDK | 17 |
| Android SDK Platform | 36 |
| Android Build Tools | 36.0.0 |
| Gradle | Gradle Wrapper پروژه |

### ۱. دریافت پروژه

```bash
git clone https://github.com/aversateam/Arya_messenger.git

cd Arya_messenger
```

### ۲. اجرای تست‌ها

```bash
./gradlew :app:testDebugUnitTest
```

### ۳. ساخت نسخه Debug

```bash
./gradlew :app:assembleDebug
```

**در ویندوز:**

```bat
gradlew.bat :app:testDebugUnitTest

gradlew.bat :app:assembleDebug
```

### 📦 خروجی APK

پس از Build موفق، فایل APK در مسیر زیر قرار می‌گیرد:

```text
app/build/outputs/apk/debug/app-debug.apk
```

> فایل `local.properties` عمداً در مخزن قرار نگرفته است. Android Studio باید مسیر Android SDK را متناسب با سیستم توسعه‌دهنده تنظیم کند.

### ۴. ساخت نسخه Release و خروجی برای دستگاه‌ها

برای امضای نسخهٔ انتشار، فایل `keystore.properties` را در ریشهٔ پروژه بساز (در `.gitignore` است):

```properties
storeFile=release.jks
storePassword=...
keyAlias=arya
keyPassword=...
```

سپس:

```bat
gradlew.bat :app:bundleRelease
gradlew.bat :app:assembleRelease
```

- `bundleRelease` فایل **AAB** می‌سازد؛ گوگل پلی خودش نسخهٔ مناسب هر معماری، تراکم صفحه و زبان را می‌سازد.
- `assembleRelease` یک APK یونیورسالِ امضاشده می‌سازد که روی هر دستگاهی از اندروید ۸ به بالا نصب می‌شود.
- پروژه در حال حاضر **هیچ کد نیتیو (`.so`) ندارد**؛ بنابراین تقسیم‌بندی ABI فعلاً خروجی‌های یکسان تولید می‌کند و لازم نیست. با اضافه‌شدن libp2p/QUIC در آینده معنا پیدا می‌کند.
- بدون `keystore.properties` بیلد موفق می‌شود اما APK امضانشده می‌ماند.

## 😀 منابع و مجوزهای ایموجی

سیستم ایموجی آریا از بخش‌هایی از پروژه Telegram اقتباس شده است.

اجزای اقتباس‌شده:

- `EmojiPack.java`
- `EmojiData.java`
- `EmojiView`
- `EmojiTabsStrip`
- `assets/emoji.pack`

لودر و داده‌های اقتباس‌شده مشمول شرایط GPLv2 یا نسخه‌های بعدی آن هستند.

همچنین فایل `emoji_names.json` بر اساس داده‌های پروژه [iamcal/emoji-data](https://github.com/iamcal/emoji-data) تهیه شده و مشمول مجوز MIT است.

حقوق و مجوز تصاویر ایموجی نیز باید مطابق منبع اصلی آن‌ها رعایت شود.

### جایگزینی تصاویر ایموجی

مسیر تصاویر:

```text
app/src/main/assets/emoji/<category>/<codepoint>.png
```

برای مثال:

```text
flags/1f1ee-1f1f7.png
```

برای جایگزینی یک ایموجی:

1. فایل PNG موردنظر را پیدا کنید.
2. تصویر جدید با ابعاد ۶۴×۶۴ پیکسل را جایگزین کنید.
3. پروژه را مجدداً Build کنید.

فایل `assets/emoji/INDEX.csv` شامل اطلاعات پوشه، نام فایل و کلیدواژه‌های ایموجی است.

**نکته فنی:** ترتیب دسته‌ها و جایگاه ایموجی‌ها در آرایه `EmojiData.data` در نگاشت تصاویر مؤثر است. بنابراین جایگزینی فایل PNG موجود امن‌تر از تغییر ترتیب یا ساختار داده‌ها است.
